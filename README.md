# Sz(8) over Q: paper, certificate and Lean formalization

This repository realizes the Suzuki group Sz(8) regularly over Q. It contains the paper, the exact data, the programs that certify the result, and a Lean 4 formalization checked by Lean's kernel.

DOI: [10.5281/zenodo.22730384](https://doi.org/10.5281/zenodo.22730384)

The main result is an explicit regular Sz(8) extension over Q(s). It comes from a degree-65 Sz(8):3 polynomial by a rational cubic base change. The specialization at s = 0, or t = -7/5, has group Sz(8) over Q. Lean separately proves the statement over Q: the Galois group of `f(X, -7/5)` is isomorphic to Sz(8).

## Quick check

`data/f.json`, `data/g.json` and `data/monodromy.json` are the compact public inputs. The certificate programs read byte-identical copies in `certificate/results/f_poly.json` and `certificate/results/g_poly.json`.

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt
make check
```

`make check` verifies:

- the digests in `certificate/manifest.json`;
- the exact cubic pullback;
- the specialization factorizations at 11 and 31;
- the group generated by the stored permutations.

It does **not** repeat analytic continuation, and it does not prove that those permutations are the polynomial's monodromy. That requires the full verification or the Lean formalization.

## Additional checks

| Command | Checks | Needs |
| --- | --- | --- |
| `make nodes` | Exact alternative to the interval node test (about 45 s) | PARI/GP |
| `make review-check` | The Appendix A polynomial and further evidence for referees | Python packages only |
| `make cubic` | Cubic discriminants, field identifications (Section 4), conductor-117 fibers, reference deck transformation | PARI/GP |
| `make reduced` | The reduced presentations (see below) | Python packages only |

**`make nodes`** interpolates the discriminant modulo 1000003 and checks its full degree and its squarefree node factor. It also checks degree-one gcds over every factor field. Combined with the characteristic-zero discriminant identity, this proves that each additional discriminant root is a single double root. The full run uses the interval proof instead. The report is written to `certificate/results/nodes_modp_check.json`.

**`make review-check`** verifies:

- every coefficient of the polynomial printed in Appendix A and its exact isomorphism with `F3(Y,4)`;
- the Frobenius patterns at 11 and 17, and the coefficient heights;
- the public F3/bridge coordinate identity and the local equation at infinity;
- the real signatures and the complex-conjugation identity for the stored permutations.

It uses certified root enclosures but does not repeat path tracking. The report is written to `certificate/results/review_evidence_check.json`.

The modular node check does not replace the characteristic-zero discriminant computation. Together, these checks are not a complete independent rerun of the generic certificate.

## Reduced presentations

- `data/F3_L3P0P4.json`: the 47-digit generator of `L(3P_0+P_4)`, bidegree (65,7). Its bridge relation to `f` is in `data/F3_bridge_psi.json`.
- `data/G3_L3P0P4_pullback.json`: its cubic pullback, 52 digits, with group Sz(8) over Q(s).
- `data/P_number_field.json`: a 68-digit monic defining polynomial of the s = 0 specialization field. The inverse isomorphism is in `data/P_number_field_verify.json` and `data/P_number_field_verify_B.json.gz`. `data/F3_spec_field_check.json` records a root of `F3(Y, -6/5)` in that field.
- `data/P_s1_number_field.json`: the monic 43-digit polynomial defining the s = 1 field. It is printed in Appendix A and verified by `make review-check`.

Heights are primitive integer heights of the coefficient vector. Digests recorded in the data files refer to the files as published here.

`make reduced` works from the data files alone, without PARI/GP or GAP. It reruns:

- the field isomorphism (`T(A) = 0 mod P` and irreducibility);
- the 52-digit specialization `F3(Y, -6/5)` defining the same field;
- the exact pullback identity for `G3` and the stated heights;
- the full bridge from `F3` to `f`.

The bridge takes about 15 minutes on 6 workers. `python3 scripts/run_reduced_presentations.py --skip-bridges` runs only the instant checks.

## Full verification

Install PARI/GP and GAP with the primitive-group library. `gp` and `gap` should be on PATH, or set `GAP_BIN` to a GAP executable. Then run:

```sh
python3 scripts/run_certificate.py --workers 4
```

By default this recomputes the exact discriminant and its roots from `f`, then runs all remaining stages, including `make cubic` and the specialization proof. Allow tens of minutes and several GB of memory.

To reuse the compressed discriminant while still re-certifying all node boxes, run:

```sh
python3 scripts/run_certificate.py --reuse-discriminant --workers 4
```

The discriminant is stored losslessly as `certificate/results/discriminant.pkl.gz`. The restore helper checks both the compressed and the uncompressed digests before restoring it. It is a pickle, so only load this trusted project artifact.

The recorded reports were produced with Python 3.11.9, python-flint 0.9.0, SymPy 1.11.1, PARI/GP 2.17.4 and GAP 4.15.1. A full rerun replaces the reports, and serialization or timings may change. After adopting its outputs, run `make manifest` to rewrite the manifest. To also store the new discriminant pickle, run `python3 scripts/write_manifest.py --pack-discriminant`.

## Lean formalization

`lean/` is a Lean 4 project. Its main theorem, checked by Lean's kernel, states that the Galois group of the specialization `f(X, -7/5)` over Q is isomorphic to Sz(8):

```lean
theorem Sz8.Galois.gal_specialization_equiv_suzuki :
    Nonempty (paperSpecialization.Gal ≃* Suzuki.Suzuki Suzuki.θ8)
```

- **Sz(8)** is Suzuki's matrix group over F_8. The isomorphism goes through its action on the 65-point ovoid.
- **Generic Galois group.** Lean also proves that the Galois group of `f` over Q(t) is the explicit group of order 87360 generated by the permutations in `data/monodromy.json`. These permutations are identified with the monodromy of certified loops, which closes the gap left open by `make check`.
- **Axioms.** Every audited theorem uses only `propext`, `Classical.choice` and `Quot.sound`. There is no `native_decide` and no `sorry`.
- **Not formalized:** the regular realization over Q(s) by the cubic base change.

The 268 generated certificate files are not stored in the repository. `make lean-data` regenerates them from the data here and checks them against the hashes pinned in `lean/provenance/generated.json`. This needs Python with python-flint and SymPy, and PARI/GP.

```sh
make lean-data
cd lean
lake exe cache get
sh tools/full_build.sh
```

With prebuilt Mathlib, the full build and audit take a little over an hour on a 12-core Apple M2 Max with 32 GB of memory. Once the project is built, `make lean-verify` reruns the audit alone. `lean/reproducibility.json` records a clean rebuild. See [`lean/README.md`](lean/README.md) for the precise statement, the trust model and the build details.

## Scope

The repository contains the independent certificate for the polynomial theorem. The discovery computations are not included: the triangle-group engine, the exact genus-six model and the modular reconstruction engine. They are not needed to verify the main theorem. Section 7 describes them and gives the prime counts and controls for the relevant Riemann–Roch computations.

## arXiv bundle

`make arxiv-bundle` creates `dist/sz8-over-q-arxiv.tar.gz`. The archive contains the LaTeX source and every `.json` and `.json.gz` file from `data/` and `certificate/`, placed below arXiv's top-level `anc/` directory.
